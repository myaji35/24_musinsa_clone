# JIEUN 홈페이지 리뉴얼 기획안

작성일: 2026-09-15 · 상태: 검토용 초안 · 범위: 기획 및 이슈 도출

## 1. 핵심 제안

리뉴얼의 첫 과제는 홈페이지의 주 이용자와 목적을 정하는 것이다. 현재는 소비자용 상품 탐색, 사업자용 상품·재고 관리, AI 운영 솔루션 소개가 한 화면에 섞여 있다. 브랜드와 이용 동선을 정리하고, 표시 정보와 실제 기능을 일치시키는 작업을 우선한다.

현재 `/`가 상품 큐레이션과 랭킹으로 구성되어 있어, 본 상세안은 **소비자용 상품 탐색 홈**을 작업 가정으로 삼았다. 이는 확정된 사업 방향이 아니다. 기존 PRD는 사업자용 의류 운영 솔루션을 설명하므로 아래 방향 선택이 선행되어야 한다.

| 방향 | 주 이용자·목적 | 첫 화면과 주요 행동 | 계획에 미치는 영향 |
|---|---|---|---|
| A. 상품 탐색 홈 — 상세안의 가정 | 스타일과 상품을 찾는 방문자 | 검색, 카테고리, 추천 상품 → 상품 상세 | 아래 화면 구성 적용 |
| B. 운영 솔루션 소개 홈 | 의류 사업자·매장 운영자 | 운영 문제와 해결 가치, 실제 기능 소개 → 관리자 로그인 또는 준비된 문의 채널 | 상품 랭킹 대신 재고·발주·고객 분석의 사용 사례 중심으로 재구성 |
| C. 두 대상의 진입점 분리 | 소비자와 사업자 | 상품 둘러보기 / 사업자 서비스라는 두 진입점 | 각 목적지와 별도 메뉴 구조를 먼저 정의 |

## 2. 조사 근거와 한계

- 조사 대상: 로컬 `musinsa_clone`의 현재 홈, 공통 레이아웃, 상품 목록·상세, 검색, 관련 컨트롤러·헬퍼·JavaScript 및 기존 PRD.
- 현재 구현 근거는 소스 코드로 확인했다. 기존 문서의 완료 표시는 현재 동작의 증거로 사용하지 않았다.
- 실제 브라우저 렌더링, 운영 서버, 실데이터, 이용 통계, 사용자 인터뷰는 검증하지 않았다. 모바일 잘림·속도·실제 이탈은 후속 검증 대상이다.
- 산출물은 이 문서와 [이슈 목록](HOMEPAGE_RENEWAL_ISSUES.md)이다. 코드 수정, 디자인 시안 제작, 배포, 외부 이슈 등록은 수행 범위에 포함하지 않는다.

## 3. 리뉴얼 목표와 범위

목표는 방문자가 JIEUN의 역할을 이해하고, 원하는 상품을 찾아 상세 정보까지 자연스럽게 이동하도록 만드는 것이다.

| 목표 | 기획 요구사항 |
|---|---|
| 서비스 이해 | JIEUN 명칭과 고객용 소개 문구를 통일하고 운영자 메뉴의 진입점을 구분 |
| 빠른 탐색 | 모바일 첫 화면에 검색·카테고리 진입점을 제공하고 검색 결과를 상단에 배치 |
| 정보 신뢰 | 가격·할인·평점·갱신 시간의 데이터 근거를 정의하고 값이 없을 때의 표시 정책 마련 |
| 끊기지 않는 동선 | 노출하는 링크의 목적지, 결과 없음, 이미지 실패, 뒤로 가기 상태까지 정의 |
| 운영 가능성 | 추천 상품 선정·교체 책임자, 게시 기준, 성과 확인 방법 정의 |

1차 범위: 홈, 공통 헤더·푸터, 홈 상품 카드, 검색·카테고리·정렬·큐레이션 연결 정책. 상품 목록·상세는 홈에서 이어지는 동선의 이슈와 요구사항까지만 포함한다.

별도 확장 범위: 결제·장바구니 시스템, 회원 체계, 개인화 추천 엔진, 운영 대시보드 개편, DB·프레임워크 교체. 홈페이지 리뉴얼의 기본 전제로 잡지 않는다.

## 4. 주요 이용 흐름

| 방문 의도 | 제안 동선 | 성공 상태 |
|---|---|---|
| 특정 상품·브랜드 탐색 | 홈 검색 → 결과 목록 → 필터·정렬 → 상세 | 검색 조건에 맞는 상세 정보 열람 |
| 취향에 맞는 상품 발견 | 홈 무드 컬렉션 → 같은 무드의 목록 → 상세 | 제목과 실제 상품 속성이 일치 |
| 인기 상품 비교 | 인기 상품 → 카테고리 → 상세 | 집계 기준을 이해하고 비교 가능 |
| 상품 재방문 | 상품 찜 → 저장 목록 → 상세 | 저장 정책과 다시 찾는 경로가 존재할 때만 제공 |
| 운영자 업무 진입 | 사업자 로그인 → 운영 메뉴 | 소비자 메뉴와 구분된 업무 진입 |

구매 기능 제공 여부가 정해지기 전까지 핵심 전환은 상품 상세 진입으로 정의한다. 실제 구매 동선이 제공될 경우 구매 지표를 별도로 추가한다.

## 5. 홈 화면 구성안 — 방향 A

| 순서 | 영역 | 내용·행동 | 노출 규칙 |
|---|---|---|---|
| 1 | 헤더 | JIEUN, 검색, 상품 탐색, 스타일 콘텐츠, 사업자 로그인 | 모바일에도 검색·메뉴 진입 제공. 연결 가능한 항목만 노출 |
| 2 | 짧은 브랜드 소개 | 예시: “일상에 맞는 취향을 찾다” + 컬렉션 보기 | 문구는 제안. 캠페인 소재가 없으면 간결한 텍스트 영역으로 운영 |
| 3 | 카테고리 | 전체·상의·아우터·바지·원피스·스커트·가방 | 공통 분류표 사용. 데이터 없는 분류의 숨김/빈 상태 정책 지정 |
| 4 | 대표 큐레이션 | 우선 1개 컬렉션, 상품 4개, 더보기 | 제목·설명·선정 기준·목적지가 완성된 컬렉션만 게시 |
| 5 | 인기 상품 | 초기 10개 제안, 카테고리·정렬, 더보기 | 판매량 집계 범위 확정. 가격순·최신순에서는 순위 배지와 랭킹 제목 제거 |
| 6 | 추가 발견 | 추가 무드 컬렉션 또는 스타일 콘텐츠 | 운영 가능한 콘텐츠가 있을 때만 추가 |
| 7 | 푸터 | 브랜드 소개, 실제 문의 경로, 준비된 정책 문서, 사업자 진입 | 고객에게 필요한 내용으로 정리하고 문서 담당자 지정 |

검색어 또는 카테고리 조건이 있으면 목록 중심 화면으로 전환한다. 결과 제목, 검색어, 선택 조건, 전체 결과 수, 초기화, 결과 목록을 먼저 보여준다. 무관한 큐레이션은 결과 위에 반복 노출하지 않는다.

### 메뉴·검색 정책

- 홈과 상품 목록의 검색·정렬 값, 카테고리 코드를 통일한다. `/search`의 독립 결과 화면 사용 여부와 기존 URL 처리 방식을 함께 정한다.
- `더보기`는 선택한 무드·카테고리를 유지한 전체 목록으로 연결한다.
- 검색 시 카테고리·정렬 유지 여부를 모든 검색창에서 일치시킨다. 본 안은 유지하고 개별 해제 기능을 제공하는 방식이다.
- 상품 목록의 `신규 상품 등록`, `수정`은 운영자 동선으로 구분한다. 메뉴 분리는 접근 권한 검증을 대체하지 않는다.
- 찜은 현재 브라우저 저장 방식이다. 1차 유지 시 “이 기기에 저장” 안내와 목록 진입을 함께 기획하고, 목록 제공이 어렵다면 노출을 보류한다.

### 표현·콘텐츠 원칙

- JIEUN 이름과 목소리를 일관되게 사용한다. 타 서비스명과 개발용 설명 문구를 점검한다.
- 흰색·중립 회색 바탕, 검정 글자, 제한된 강조색을 기본안으로 삼는다. 색상은 할인·선택·상태 등 의미별로 일관되게 사용한다.
- 상품 카드에서 이미지 → 브랜드·상품명 → 실제 판매가 → 근거 있는 보조정보 순서를 유지한다.
- 모바일 2열, 데스크톱 4~5열을 출발점으로 검토한다. 글자 가독성과 상품명 길이에 따라 조정하며 실기기 검증 전 확정하지 않는다.
- 찜·검색 등 아이콘에는 동작 이름과 키보드 초점 표시를 제공한다. 터치 환경에서 주요 조작을 항상 발견할 수 있게 한다.
- “맞춤 추천”은 실제 개인화 근거가 있을 때만 사용한다. 현재는 무드별 상품 모음으로 설명한다.

## 6. 상태별 요구사항

| 상태 | 화면 정책 |
|---|---|
| 검색 결과 0개 | 검색어·적용 조건, 결과 없음 설명, 조건 해제, 전체 상품 이동 |
| 컬렉션 상품 부족 | 실제 상품 수만 노출. 0개인 컬렉션은 숨김 |

| 리뷰 없음 | “리뷰 없음” 표시, 임의 평점 표시 금지 |
| 할인 정보 없음 | 판매가만 표시 |
| 품절·옵션 미선택 | 상세의 상태와 안내를 일치시키고 가능한 행동을 명시 |
| 준비되지 않은 기능 | 작동하는 것처럼 보이는 버튼·링크를 노출하지 않음 |
| 뒤로 가기·새로고침 | 검색어·분류·정렬 및 가능한 범위에서 목록 위치 복원 |

## 7. 운영과 성과 측정 계획

추천 상품에는 선정 기준, 노출 순서, 게시·종료일, 담당자, 연결 URL을 기록한다. 판매가·할인·배송·리뷰는 데이터 출처와 갱신 책임을 정한다. 랭킹은 집계 기간과 마지막 집계 시각을 정의한 뒤 표시한다.

현재 코드 조사에서 대표적인 이용 행동 분석 연동을 찾지 못했다. 운영 측 별도 도구의 존재 여부는 미확인이다. 현황 수치나 개선율을 추정해서 목표로 제시하지 않는다.

| 지표 | 정의 | 목적 |
|---|---|---|
| 홈 → 상세 진입률 | 홈 방문 세션 중 상품 상세로 이동한 세션 비율 | 상품 탐색 연결 성과 |
| 검색 무결과율 | 결과 0건 검색 횟수 / 전체 검색 횟수 | 분류·검색 품질 |
| 검색 후 상세 진입률 | 검색 사용 세션 중 검색 결과에서 상세로 이동한 세션 비율 | 검색의 유용성 |
| 큐레이션 클릭률 | 컬렉션 노출 세션 중 상품 또는 더보기 클릭 세션 비율 | 콘텐츠 기여 |

후속 계측 후보: `home_view`, `search_submit`, `search_results_view`, `collection_impression`, `collection_click`, `product_click`. 상품 ID, 영역, 정렬, 결과 수, 기기 구분 등 필요한 항목만 정의하며 검색어 원문 수집은 별도 보관 정책을 정한 뒤 판단한다.

동일한 이벤트 정의로 리뉴얼 전 기준선을 수집하고, 공개 후 같은 기간·기기 구분으로 비교한다. 트래픽과 계절성에 따라 비교 기간을 정하고 수치 목표는 기준선 확인 후 합의한다.

## 8. 기획 진행 순서와 완료 조건

1. 방향 확정: A/B/C, 핵심 이용자, 핵심 행동, 구매 지원 범위 결정.
2. 정보구조 확정: 메뉴·URL 대응표, 홈 영역 순서, 모바일 검색 흐름, 운영자 진입 정책.
3. 콘텐츠·데이터 정의: 브랜드 문구, 상품 카드, 랭킹 기준, 빈 상태, 운영 담당 역할.
4. 이슈 정리: [이슈 목록](HOMEPAGE_RENEWAL_ISSUES.md)의 우선순위·의존성·완료 기준 검토.
5. 후속 검증 계획: 브라우저에서 모바일·데스크톱 동선, 검색 캐시, 이미지 실패, 키보드 조작을 확인할 항목 확정.

구현 착수 전 미결정 사항: 홈페이지 주 대상, 직접 판매/외부 구매 연결/탐색 전용 중 서비스 범위, 운영 가능한 콘텐츠·상품 데이터, 실제 문의 채널, 콘텐츠 책임자, 기존 분석 도구 유무.

이 문서는 위 의사결정을 위한 초안이며 구현 착수나 일정·담당자 배정을 의미하지 않는다.
