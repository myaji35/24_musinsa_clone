## HR-01 · 주 이용자·브랜드·운영 메뉴 혼재

- 근거: `app/views/home/index.html.erb:12`는 “무신사 랭킹”, `app/views/layouts/application.html.erb:57`은 JIEUN, 같은 파일 `:70`부터 소비자 메뉴와 재고·대시보드·거래처·발주가 함께 노출된다. `app/views/products/index.html.erb:5`는 공개 목록을 “상품 관리”로 표시하고 등록·수정 링크를 노출한다. 기존 `../legacy_docs/prd.md`의 목적은 사업자용 운영 솔루션이다.
- 영향: 홈페이지가 누구를 위한 것인지와 상품 메뉴의 목적이 불명확하다. 메뉴 노출만으로 권한 우회가 있다고 판단하지는 않는다.
- 제안: 기획안 A/B/C 중 방향을 선택하고 이름·소개·메뉴·운영자 진입점을 일치시킨다.
- 완료 기준: 대상별 메뉴·목적지 대응표가 있고, 소비자 동선에 업무용 등록·수정 유도가 섞이지 않는다.
- 의존성: 전체 화면 구성에 선행.

## HR-02 · 근거 없는 고정 상품 지표

- 제안: 데이터가 없는 지표는 숨기거나 없음 상태로 표시하고, 카드·상세 가격과 배송 정책을 통일한다.
- 완료 기준: 할인 없음·리뷰 없음·장바구니 비어 있음 사례에서 임의 숫자가 노출되지 않고 모든 혜택 문구의 데이터 출처가 정해진다.

## HR-03 · 구매 동선과 제공 기능 불일치

- 완료 기준: 공개 버튼마다 실행 가능한 목적지가 있고, 구매 미지원 시 구매 가능한 화면으로 오해시키지 않는다.

## HR-04 · 검색 결과 캐시 키 누락

- 근거: `app/views/home/index.html.erb:31`의 그리드 캐시 키에는 최대 수정 시각·카테고리·정렬만 있고 `params[:q]`가 없다. `app/controllers/home_controller.rb:28`은 검색어에 따라 다른 목록을 만든다. `config/environments/production.rb:16`은 조각 캐시를 활성화한다.
- 영향: 두 검색 결과의 최대 수정 시각과 다른 키가 같으면 먼저 저장된 다른 검색 결과가 표시될 위험이 있다. 실제 재현은 하지 않았다.
- 후속 검증: 캐시가 켜진 격리 환경에서 같은 최신 수정 상품을 포함하되 나머지는 다른 검색 A/B를 순차 조회하고 결과 ID를 대조한다. 검색 결과가 없는 경우도 확인한다.
- 완료 기준: 서로 다른 검색어의 결과가 섞이지 않고, 상품 변경·삭제 후에도 합의한 갱신 기준을 충족한다.

- 제안: 첫 화면 검색·메뉴 진입, 주요 카테고리 우선 배치, 검색 상태에서 결과 우선 배치를 설계한다.
- 완료 기준: 360·390·768·1280px 검증 화면에서 검색·메뉴에 접근 가능하고 주요 조작과 텍스트가 잘리지 않는다.

## HR-07 · 검색 경로와 조건 일관성

- 영향: 진입 위치에 따라 조건이 사라지고 검색 URL의 역할이 불명확하다. 홈 검색 후에도 검색과 무관한 큐레이션이 결과 위에 남는다.
- 제안: 대표 검색 경로, 공통 분류·정렬 값, 조건 유지·해제 정책을 정한다.
- 완료 기준: 같은 입력은 같은 결과·선택 상태를 표시하고, 직접 URL 접근·새로고침·뒤로 가기에서도 상태를 이해할 수 있다.
- 의존성: HR-01.

## HR-08 · 결과 수·더보기·빈 상태

- 근거: `app/controllers/home_controller.rb:45`는 결과를 50개로 제한하고, `app/views/home/_filter_section.html.erb:24`는 제한된 관계의 개수를 “총” 개수로 사용한다. `app/views/home/index.html.erb:32`의 그리드는 빈 결과 안내와 페이지 이동 UI가 없다.

## HR-09 · 랭킹과 실제 집계 기준 불일치

- 완료 기준: 선택한 정렬과 표시가 일치하고 집계 근거가 없는 갱신 시간은 표시하지 않는다.

- 제안: 링크와 버튼의 독립 조작, 항상 찾을 수 있는 표시, 상태 안내, 기기 저장 정책과 목록 진입을 함께 설계한다.
- 완료 기준: 터치·Tab·Enter/Space로 상세 이동과 찜을 구분해 조작하고, 저장한 상품을 다시 찾을 수 있다. 저장소 제한·오류 시 안내 정책도 있다.

- 영향: JavaScript·이미지 요청 실패 시 빈 이미지가 남을 수 있다. 첫 화면 이미지 로딩이 늦어지는지는 측정이 필요하며 성능 장애로 확정하지 않는다.
- 제안: 실패 대체 표시와 첫 화면 이미지 우선 로딩 정책을 정하고 네트워크 조건별로 검증한다.
- 완료 기준: 정상·저속·이미지 404·JavaScript 실패 상태에서도 상품명·링크가 유지되고, 이미지 영역이 불필요하게 흔들리지 않는다.

## HR-13 · 큐레이션 선정·운영 정책

- 근거: `app/controllers/home_controller.rb:53`은 3개 무드를 하드코딩하고 JSON 전체 문자열의 LIKE 검색, 조회수 정렬, 1시간 캐시를 사용한다. 모델에는 `app/models/product.rb:30`의 mood 전용 scope가 별도로 있다. 큐레이션은 홈의 검색·카테고리 조건을 적용하지 않는다.
- 영향: 의도한 mood 필드 외의 문자열에 반응할 가능성이 있고, 운영자가 제목·상품·갱신 시점을 일관되게 관리하기 어렵다.
- 제안: 무드 필드 기준, 상품 선정·교체 규칙, 담당 역할, 갱신 허용 시간, 검색 중 노출 정책을 정의한다.
- 완료 기준: 다른 속성에만 같은 문자열이 있는 상품이 잘못 포함되지 않고, 빈 컬렉션·상품 삭제·품절·속성 변경의 표시 정책이 명확하다.

## HR-14 · 문서 정보·공통 접근성·측정

- 제안: 방향에 맞는 제목·소개·대표 이미지, 문서 언어·제목 구조·입력 이름·초점 정책을 정의한다. 기존 계측 여부를 확인하고 기획안의 핵심 이벤트를 설계한다.
- 완료 기준: 홈 문서와 검색·공유 설명이 서비스 목적에 맞고 키보드·화면 읽기 검증 항목을 통과한다. 핵심 지표의 분모·분자·수집 시점·담당 역할이 정의된다.

## HR-15 · /admin 상품 엑셀 임포트

- 요청: 엑셀로 받은 상품 대표 이미지와 상세정보를 관리자 화면에서 일괄 등록·수정한다.
