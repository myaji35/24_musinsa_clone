# 스파이크: 외부 채널 주문 수집 (ISS-030)

작성: 2026-10-18 · 상태: 조사 완료(구현 없음) · 범위: 코드 읽기와 기존 문서 기준. 외부 API 호출·과금 없음.

## 1. 결론

- **지금은 만들지 않는다.** EPIC v2 / PRD v2 에서 Epic 8(외부 채널 통합)은 "폐기, 스파이크만 보존"이다. 무신사 입점은 판매 경로가 아니다.
- **나중에 필요해지면 붙일 자리는 이미 있다.** ISS-015 에서 만든 `Orders::Intake`(app/services/orders/intake.rb)가 주문 수집의 단일 진입점이다. 외부 채널 어댑터는 이 서비스를 호출하는 얇은 계층으로 두면 된다.
- 재검토 시점은 "자사몰 첫 매출 이후 외부 마켓 입점을 실제로 결정했을 때"다.

## 2. 현재 진입점 (사실 확인)

`Orders::Intake.new(items:, address:, save_consent:, birth_year:).call`

| 입력 | 형태 | 비고 |
|---|---|---|
| items | `[{variant_id:, quantity:}]` | variant 가 없거나 가격이 없거나 수량이 양의 정수가 아니면 `InvalidInput` |
| address | recipient_name, phone, postal_code, address1, address2, country_code | 국내(KR)는 우편번호 5자리 검증 |
| save_consent | boolean | 배송지 보관 동의. 기본 false |
| birth_year | 선택 | 익명 고객 식별에 사용 |

동작: 한 트랜잭션 안에서 배송지 생성 → 익명 고객 조회/생성(전화 뒤 4자리 + 출생연도) → 항목별 `Order`(status `pending`) 생성. 결과는 `Result`(`orders`, `checkout_number`, `errors`)로 돌려준다. `checkout_number` 는 `CHK-YYYYMMDD-XXXXXXXX` 형식이다.

호출처는 자사몰 `CheckoutsController` 하나뿐이다.

## 3. 외부 채널을 붙일 때 맞지 않는 부분

1. **상품 매핑 부재.** 외부 채널의 상품·옵션 ID 를 우리 `Variant` 로 바꾸는 표가 없다. 가장 큰 공백이다. 필요하면 `channel_listings(channel, external_sku, variant_id)` 같은 매핑 테이블이 선행된다.
2. **가격 출처.** Intake 는 항상 `variant.product.price` 로 금액을 계산한다. 외부 채널의 판매가·할인·수수료와 달라진다. 채널 주문은 채널이 알려준 결제 금액을 받아야 한다.
3. **주문 출처 구분 없음.** `orders` 에 channel / external_order_id 컬럼이 없다. 같은 외부 주문을 두 번 수집(중복)하는 것을 막을 키가 없다. 멱등성 키(채널 + 외부 주문번호 유니크 인덱스)가 필요하다.
4. **개인정보.** 외부 채널은 수령인·전화·주소를 이미 보관한다. 우리 쪽 복제는 ISS-058 C안(동의 기반 보관, 자동 파기)에 맞춰야 한다. 채널 주문은 `save_consent` 를 false 로 두고 출고 후 파기하는 쪽이 안전하다.
5. **재고 차감 시점.** 자사몰 주문은 `pending` 으로 시작한다. 외부 채널 주문은 이미 결제가 끝난 상태로 들어오므로 시작 상태와 재고 차감 규칙을 따로 정해야 한다.
6. **수집 방식.** 무신사 파트너 등 대부분 공개 API 가 없거나 계약이 필요하다. 후보는 (a) 채널 제공 API/웹훅, (b) 관리자 엑셀·CSV 업로드, (c) 화면 크롤링이다. (c)는 이용약관·법적 위험이 있어 채택하지 않는다.

## 4. 권장 단계 (재개 시)

| 단계 | 내용 | 비고 |
|---|---|---|
| 0 | 대상 채널과 수집 방식 결정 | 대표님 결정 사항. 계약·약관이 걸림 |
| 1 | CSV 업로드 방식으로 시작 | 외부 계약 없이 가능. 관리자 화면 + 매핑 테이블 |
| 2 | `orders` 에 channel, external_order_id 추가 + 유니크 인덱스 | 마이그레이션 포함이라 배포 전 확인 필요 |
| 3 | `Orders::Intake` 에 채널 주문용 옵션 추가 | 가격·시작 상태·동의 처리 분기 |
| 4 | API/웹훅 연동 | 채널별 인증키 필요 → 시크릿 발급 사안 |

## 5. 위험과 비용

- 개발 비용: 단계 1~3 은 중간 규모(M). 단계 4 는 채널마다 별도.
- 외부 과금: 현 시점 없음. 단계 4 에서 채널 API 이용료·수수료가 생길 수 있다.
- 법적: 크롤링 금지. 개인정보는 ISS-058 정책 준수.

## 6. 판단 요약

스파이크 목적(붙일 수 있는지, 어디가 비는지)은 달성했다. 진입점은 준비되어 있고, 비는 곳은 상품 매핑 / 출처·멱등성 키 / 가격·상태 규칙 세 가지다. 외부 채널을 실제로 열기로 결정되기 전까지 구현하지 않는다.
