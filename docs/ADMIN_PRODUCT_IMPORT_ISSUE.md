# HR-15 · /admin 상품 엑셀 임포트

작성일: 2026-09-15 · 유형: 기능 기획 / 상위 이슈 · 우선순위: P1
상태: 기획 완료·파일 형식 확인 대기 / 구현 미착수
연계: [홈페이지 리뉴얼 이슈 목록](HOMEPAGE_RENEWAL_ISSUES.md)

## 1. 요청과 목표

운영자가 엑셀로 받은 상품 대표 이미지와 상세정보를 `/admin`에서 일괄 등록·수정한다. 업로드 내용을 먼저 검증하고 상품별 이미지와 변경 내용을 확인한 뒤 반영할 수 있어야 한다.

사용자 확정 요구: 엑셀 입력, 대표 이미지·상세정보 수신, `/admin` 임포트 진입점, 현 단계는 기획 및 이슈화까지.

이 문서의 지원 형식·용량·필드·처리 정책은 구현을 위한 제안이다. 실제 공급 파일은 아직 확인하지 않았으므로 URL 이미지와 엑셀 삽입 이미지의 대응을 구분해 작성한다. 샘플 확인 후 템플릿과 지원 가능한 삽입 이미지 형식을 확정한다.

## 2. 현재 구현과 차이

| 확인한 현재 상태 | 필요한 변화 | 근거 |
|---|---|---|
| `/admin` 및 임포트 라우트 없음 | 관리자 진입·업로드·검증·결과 화면 추가 | `config/routes.rb` |
| `require_admin`은 로그인 여부만 검사하고 User에 관리자 역할 필드 없음 | 임포트 권한을 명시적으로 정의하고 서버에서 검사 | `app/controllers/application_controller.rb`, `app/models/user.rb`, `db/schema.rb` |
| 상품명·가격·브랜드·카테고리 필수, 설명 최대 500자 | 기존 조건 유지와 긴 상세정보 저장 구조 추가 | `app/models/product.rb`, `app/views/products/_form.html.erb` |
| 대표 이미지는 첨부 1개 또는 URL, 첨부 이미지 우선 표시 | URL·삽입 이미지를 동일 첨부 체계로 저장하고 교체 정책 정의 | `app/models/product.rb`, `app/helpers/image_helper.rb` |
| 상품 단위 외부 고유코드 없음. `sku_code`는 옵션에 존재 | 원본 상품을 식별할 수입처·상품코드 매핑 추가 | `db/schema.rb` |
| 상품 공개 상태 구분 없음, 홈·목록은 전체 상품 조회 | 신규 임포트 상품의 초안 상태와 공개 조회 조건 추가 | `app/controllers/home_controller.rb`, `app/controllers/products_controller.rb` |
| 홈은 한글 카테고리를 영어로 변환하고 등록 폼은 한글 입력 | 임포트·수동 등록·탐색이 공유할 분류 기준 필요 | `app/controllers/home_controller.rb`, `app/views/products/_form.html.erb` |

## 3. 제공 범위

포함: `.xlsx` 업로드, 템플릿 다운로드, 원본 열 연결, 상품 기본정보·대표 이미지·상세정보 등록, 기존 상품 수정, 검증·미리보기, 실행 결과와 이력, 실패 행 재처리.

대표 이미지 입력은 URL 또는 엑셀에 삽입된 이미지 1개를 지원 목표로 한다. 삽입 이미지는 상품 행과 명확히 연결되는 경우에 한하며, 호환 형식은 실제 파일로 검증한다. 상세정보는 긴 설명 텍스트와 소재·제조국·세탁방법·사이즈 안내를 기본으로 한다. 상세 이미지 URL 목록도 선택 입력으로 기획한다.

별도 후속 범위: 옵션별 SKU·바코드·실재고 일괄 조정, 주문·리뷰·판매량 임포트, 임의 HTML 상세페이지, OCR로 이미지 내용을 텍스트로 변환, `.xls`·`.xlsm`·CSV, 이미지 ZIP 별도 업로드, 자동 동기화. 신규 상품은 옵션·재고를 임의 생성하지 않고 기존 상품의 해당 데이터도 변경하지 않는다.

## 4. 관리자 화면과 동선

`/admin` → 상품 관리 → 엑셀 임포트 → 파일 업로드 → 시트·열 연결 → 검증·미리보기 → 가져오기 실행 → 결과·이력 → 상품 검토·공개

| 제안 경로 | 화면·행동 |
|---|---|
| `/admin` | 상품 관리, 엑셀 임포트, 최근 임포트 결과 진입 |
| `/admin/product_imports` | 파일명·실행자·상태·시각·신규/수정/실패 건수별 이력 |
| `/admin/product_imports/new` | 템플릿 다운로드, 공급처 선택, 신규만/신규+수정 선택, 파일 업로드 |
| `/admin/product_imports/:id` | 시트·열 연결, 검증 진행, 행별 미리보기, 변경 전후 비교, 실행 및 결과 |
| `/admin/products` | 초안 상품 검토, 수정 상품 확인, 선택 상품 공개 |

화면에서 업로드와 상품 저장을 구분한다. 업로드·검증만으로 공개 상품을 생성하거나 변경하지 않는다. 실행 화면은 `신규 20 · 수정 5 · 변경 없음 2 · 오류 3`과 같은 요약과 실제 반영 대상 수를 표시한다.

미리보기 표: 선택, 원본 행 번호, 상품코드, 대표 이미지, 상품명, 가격, 신규/수정/변경 없음/오류, 오류 설명. 상세 펼치기에서 긴 설명·상세 이미지·필드별 전후 값을 확인한다. 대표 이미지가 교체되면 이전 이미지와 새 이미지를 나란히 표시한다.

## 5. 엑셀 입력 규격 초안

기본 템플릿은 `상품` 시트에 헤더 1행, 상품당 데이터 1행이다. 다른 양식은 운영자가 시트·헤더 행을 선택하고 열을 연결한다. 필수 열이 없으면 실행할 수 없다. 숨겨진 행·시트는 기본 제외하고 제외 개수를 알린다. 상품 데이터 영역의 병합 셀은 해제 안내를 제공한다.

| 열 | 신규 등록 | 형식·예시 | 저장·검증 정책 |
|---|---|---|---|
| 상품코드 | 필수 | 텍스트 `000123-A` | 공급처 내 고유. 앞자리 0 보존. 이름으로 중복 추정 금지 |
| 상품명 | 필수 | 데일리 코튼 셔츠 | 최대 200자 |
| 브랜드 | 필수 | JIEUN | 앞뒤 공백 제거 |
| 카테고리 | 필수 | 상의 | 공통 분류표와 매핑. 알 수 없는 값은 오류 |
| 판매가 | 필수 | `39000` 또는 `39,000` | KRW 정수, 0보다 큼. 통화 혼재·음수·수식은 오류 |
| 대표이미지URL | 조건부 필수 | 직접 이미지 HTTPS 주소 | URL 또는 삽입 이미지 중 정확히 하나 선택 |
| 대표이미지 | 조건부 필수 | 해당 열·상품 행에 연결된 삽입 이미지 1개 | URL과 동시에 있으면 선택 필요. 모호한 행 연결은 오류 |
| 요약설명 | 선택 | 짧은 상품 소개 | 기존 description, 최대 500자 |
| 상세설명 | 조건부 필수 | 줄바꿈 포함 설명 | 신규 긴 텍스트 필드, 최대 20,000자 제안. 자르지 않고 초과 오류 |
| 소재 / 제조국 / 세탁방법 / 사이즈안내 | 선택 | 각각 별도 열 | 표시명 고정, 빈 항목 숨김. 사이즈 안내는 설명용이며 SKU 생성 아님 |
| 상세이미지URL | 조건부 필수 | 셀 내 줄바꿈으로 URL 나열 | 순서 유지, 최대 10개 제안. 같은 목록 내 중복은 오류 |

신규 상품은 상세설명 또는 상세이미지 중 하나 이상 필수다. 상세정보가 이미지뿐인 경우에도 임의로 내용을 추출하지 않고 입력받은 이미지를 순서대로 표시한다. 구조화 항목별 최대 길이는 템플릿 정의에 명시한다(각 2,000자 제안).

공급처는 업로드 화면에서 지정하고 파일 전체에 적용한다. 하나의 파일에 서로 다른 공급처가 섞인 경우 나눠 업로드하도록 안내한다. 상품코드는 텍스트 형식을 안내하고, 숫자 변환으로 이미 없어진 앞자리 0이나 긴 코드의 정밀도는 복원했다고 가정하지 않는다.

수식 셀은 실행하거나 저장된 계산 결과로 대체하지 않고 값 붙여넣기를 안내한다. 알 수 없는 열은 무시 대상 목록에 보여주며, 제목이 유사하다는 이유로 자동 확정하지 않는다. 선택하지 않은 시트도 명시한다.

## 6. 이미지 처리 정책

- URL: 이미지 파일로 직접 접근 가능한 HTTPS 주소를 받는다. 로그인 필요 링크·공유 페이지·만료된 링크는 행 오류와 수정 방법을 표시한다.
- 삽입 이미지: 대표이미지 열과 원본 행 번호를 기준으로 연결하고 미리보기에 표시한다. 복수 행에 걸친 배치, 한 행의 복수 대표 이미지, 행 연결이 불명확한 이미지는 임의 선택하지 않는다.
- 일반 삽입 개체, 셀 내 이미지, `IMAGE()` 수식 등 공급 파일의 유형을 샘플 단계에서 구분한다. 수식 방식은 기본 미지원이며, 파서가 읽지 못하는 이미지를 누락한 채 성공으로 처리하지 않는다.
- JPEG·PNG·WebP, 이미지당 최대 10MB를 제안한다. 확장자뿐 아니라 실제 이미지 형식·디코딩 여부·픽셀 수 제한을 검사한다. SVG 등 다른 형식은 변환 안내를 제공한다.
- 검증 단계에서 이미지 파일을 비공개 임시 저장하고 해시를 고정한다. 실행 시 미리보기에서 본 파일을 사용하며 원격 URL을 다시 가져와 다른 이미지로 바뀌게 하지 않는다.
- 저장은 기존 대표 이미지 첨부 체계를 재사용하고 상세 이미지는 순서가 있는 별도 첨부 구조를 추가한다. 원본 URL은 출처용으로 보관하되 공개 화면의 외부 링크에만 의존하지 않는다.
- 교체는 새 이미지 저장이 성공한 뒤 적용한다. 실패한 상품의 기존 대표·상세 이미지는 유지한다. 첨부 이미지와 기존 image_url의 표시 우선순위도 함께 처리한다.
- 서버의 원격 다운로드는 내부·로컬·메타데이터 주소 및 비HTTP 계열을 차단하고, DNS 해석·리다이렉트마다 목적지를 검사한다. 요청 시간·횟수·파일 크기를 제한한다. URL 쿼리의 인증 토큰은 이력·오류 보고서에 그대로 노출하지 않는다.

## 7. 신규·중복·수정 정책

식별 키는 **공급처 ID + 원본 상품코드**다. 상품과 연결하는 매핑에 유일성 제약을 둔다. 기존 상품에 매핑이 없으면 관리자에게 연결 여부를 검토하게 하고 상품명·가격·이미지 유사도로 자동 덮어쓰지 않는다.

| 상황 | 처리 |
|---|---|
| 새 코드 | 신규 상품 초안 생성 |
| 기존 코드 + 기본 모드 `신규만` | 건너뜀, 사유 표시 |
| 기존 코드 + `신규+수정` | 변경 필드 미리보기 후 실행 대상 선택 |
| 같은 파일 내 중복 코드 | 해당 코드의 모든 행 오류. 첫 행/마지막 행 임의 선택 금지 |
| 동일 값 재입력 | 변경 없음. 새 상품·첨부·수정 이력 중복 생성 방지 |
| 수정 시 빈 셀 또는 연결하지 않은 열 | 기존 값 유지. 신규 필수값 누락은 오류 |
| 기존 값을 삭제해야 함 | 1차 임포트는 빈 셀 삭제 미지원. 개별 상품 편집에서 처리 |
| 상세이미지 목록이 채워진 수정 행 | 전체 목록 교체로 표시하고 이전/새 목록 비교. 빈 셀은 유지 |
| 파일에 없는 기존 상품·옵션 | 삭제하거나 품절 처리하지 않음 |
| 미리보기 후 기존 상품 변경 | 충돌 표시 후 재검증. 다른 관리자의 최신 변경을 덮어쓰지 않음 |

수정은 매핑된 허용 필드만 반영한다. 재고·옵션·주문·리뷰·판매량·공개 상태를 파일로 바꾸지 않는다. 기존 공개 상품의 내용은 실행 시 반영됨을 미리보기에서 표시한다. 신규는 초안으로 저장하고 운영자가 별도로 공개한다. 초안은 홈·검색·상세 직접 URL·관련 상품·스타일 연결·외부 상품 API 등 모든 공개 경로에서 제외해야 한다. 기존 상품의 공개 상태는 기존 노출을 유지하도록 전환안을 마련한다.

## 8. 검증·실행·실패 복구

상태 흐름: 업로드 → 검증 중 → 실행 가능 또는 검증 오류 → 실행 중 → 완료 / 일부 실패 / 실패. 검증 전·실행 전에는 취소 가능하며, 실행 도중 중단·전체 되돌리기는 1차 제공하지 않는다.

1. 파일·시트·헤더·행 수·열 연결을 검사한다. 파일 자체가 잘못됐으면 전체 실행 불가다.
2. 필드·코드 중복·카테고리·이미지 접근·형식을 행별 검증한다. 원본 행 번호는 항상 보존한다.
3. 오류가 있으면 기본 실행을 막는다. 운영자가 `정상 행만 가져오기`를 명시적으로 선택하면 오류 행 제외 건수와 반영 대상을 확인한 뒤 진행할 수 있다.
4. 비공개 저장한 파일·매핑·정규화 데이터·이미지 해시·대상 상품 버전을 묶어 실행 대상을 고정한다. 설정이나 파일 변경은 재검증한다. 실행 시 권한과 대상 버전을 다시 검사한다.
5. 백그라운드에서 상품 한 건 단위로 기본정보·상세정보·이미지 연결을 원자적으로 반영한다. 파일 전체가 하나의 거래인 것은 아니며 실행 중 실패 시 이미 성공한 상품은 유지된다.
6. 결과에서 신규·수정·변경 없음·건너뜀·오류·실행 실패 수를 구분한다. 실패 행만 재검증·재시도하고 성공 행을 중복 실행하지 않는다. 이중 클릭·작업 재전달·동시 파일 업로드도 코드 유일성과 실행 키로 중복 반영을 방지한다.
7. 실패 내역을 `.xlsx`로 제공한다. 원본 행·상품코드·열 이름·오류 코드·사유·수정 안내를 포함한다. 예: `12행 / 판매가 / INVALID_PRICE / 0보다 큰 원화 금액이 필요합니다`.

에러 파일의 사용자 입력은 문자열로 기록해 수식으로 실행되지 않게 한다. 삽입 이미지는 오류 보고서에서 다시 제공하지 않을 수 있으므로, 원본 파일 보존과 원본 행 기준 수정 후 재업로드 방법을 안내한다. 성공 상품의 변경 기록과 이전 이미지 참조를 보관하되 자동 복원 버튼이 있다고 약속하지 않는다.

## 9. 운영 제한·권한·이력

- 초기 제한 제안: 파일당 1,000행·50MB, 작업당 다운로드/추출 이미지 합계 500MB. 압축 해제 크기·항목 수·픽셀 수·작업 시간·동시 작업 수에도 상한을 둔다. 구체적 실행 시간과 처리량은 실제 샘플로 측정 후 확정한다.
- 관리자 권한 검사를 업로드·검증·실행·미리보기·이력·원본 및 오류 파일 다운로드에 적용한다. 비로그인은 로그인으로, 로그인한 비관리자는 접근 거부한다. 로그인 후 `/admin`으로 안전하게 복귀할 수 있게 한다.
- 현 로그인 사용자 전체를 자동 관리자로 승격하지 않는다. 관리 권한을 부여할 운영 계정을 식별하고 역할 부여 방식을 별도로 정한다.
- 원본 파일·임시 이미지·오류 보고서는 비공개 저장한다. 원본/오류 파일 30일, 미실행 임시 이미지 7일, 실행 이력·변경 기록 180일 보관을 초안으로 제안한다. 적용된 상품 이미지는 임시 정리 대상에서 제외한다.
- 이력: 실행자, 공급처, 원본 파일명·해시, 템플릿/매핑 버전, 업로드·검증·실행 시각, 상태, 처리 수, 상품별 생성·변경 필드·실패 사유. 원본 토큰이나 불필요한 개인정보는 로그에 남기지 않는다.
- 홈·상품 카드·큐레이션 캐시의 갱신도 반영 완료 조건에 포함한다. 신규 공개와 이미지·상세 수정 후 이전 내용이 남지 않는지 확인한다.

## 11. 인수 기준

- [ ] `/admin`에서 템플릿 다운로드와 임포트 화면에 접근하고, 권한 없는 사용자는 직접 URL·다운로드 접근도 차단된다.
- [ ] URL 이미지·지원 대상으로 확정한 삽입 이미지 샘플 각각에서 상품 행과 대표 이미지가 정확히 연결된다.
- [ ] 신규 3개·수정 2개·변경 없음 1개·오류 2개 샘플의 미리보기와 실행 결과 수가 일치한다. `정상 행만` 선택 여부에 따라 실행 제한이 작동한다.
- [ ] 업로드·미리보기만으로 상품이 생성되거나 기존 상품·공개 이미지가 바뀌지 않는다.
- [ ] 필수 누락·알 수 없는 카테고리·음수/수식 가격·중복 코드·설명 길이 초과·손실된 코드 형식에 행·열 단위 오류가 표시된다.
- [ ] 이미지 404·만료 링크·지원하지 않는 삽입 형식·모호한 이미지 배치·과대 파일은 누락 성공 처리 없이 오류로 보고된다.
- [ ] 내부 주소 및 리다이렉트 우회 다운로드, 손상·과대 압축 엑셀, 수식 재실행을 방지하는 검증을 수행한다.
- [ ] 긴 상세설명은 줄바꿈과 내용이 보존되고, 상세이미지는 입력 순서로 표시된다. HTML은 텍스트로 취급하며 실행되지 않는다.
- [ ] 동일 파일 재실행·실패 재시도·동시 임포트에서 상품과 이미지가 중복 생성되지 않는다.
- [ ] 빈 수정 셀은 기존 값을 유지하고, 실패 상품의 기존 설명·이미지·재고·옵션·주문은 유지된다.
- [ ] 미리보기 이후 수정된 상품은 충돌로 표시한다. 서버 중단 뒤 재시도에서 성공한 상품을 다시 반영하지 않는다.
- [ ] 신규 상품은 초안이며 모든 공개 조회 경로에서 제외된다. 검토 후 공개하면 대표 이미지·상세정보가 홈 및 상세에 반영된다.
- [ ] 기존 공개 상품 수정은 안내한 실행 시점에 반영되고, 실패한 이미지 교체나 남은 캐시로 잘못된 내용이 보이지 않는다.
- [ ] 오류 엑셀에 원본 행과 수정 방법이 있고, 성공/제외/실패 합계가 전체 처리 대상 수와 일치한다.
- [ ] 1,000행과 이미지 포함 파일을 제한 범위에서 처리하며 진행 상태·중단 복구·파일 정리 결과를 검증한다. 처리 시간은 측정값으로 기록한다.

## 12. 선행·연계 사항

- HR-07: 공통 카테고리·검색 기준과 연결한다. 임포트한 상품이 저장은 되지만 홈 분류에서 빠지는 상황을 검증한다.
- HR-02: 실제 할인·평점이 없는 임포트 상품에도 고정 할인율·평점이 붙는 기존 표시 문제는 함께 해결해야 한다.
- HR-04 / HR-12 / HR-13: 캐시·이미지·큐레이션의 등록·변경 후 갱신 확인.
- HR-11: 옵션·재고 기능은 이번 임포트에서 생성하지 않으며 상품 상세의 표시 가능 상태를 별도로 검토한다.

미결정: 실제 엑셀 양식과 이미지 유형, 공급처 상품코드 유무, 상세 텍스트/이미지 비중, 통상 파일 크기·상품 수, 운영 계정. 샘플 확인 전에는 모든 Excel 이미지 형식을 지원한다고 확정하지 않는다. 라이브러리 선정·개발·테스트 실행은 후속 구현 단계다.

## 13. 후속 AI 콘텐츠 제작 연계

[HR-16 고객군 분석 기반 AI 피팅 이미지·5초 영상](ADMIN_AI_FITTING_CONTENT_ISSUE.md)을 후속 이슈로 연결한다. 임포트 완료 상품의 원본 이미지·상품코드·색상·상세정보·파일 해시를 생성 작업의 입력으로 제공한다. 원본을 보존하고 누끼·보정·피팅 이미지·영상은 별도 자산으로 관리한다.

임포트 결과에 `AI 콘텐츠 제작` 진입을 제공하되 생성 실행과 비용 확인은 해당 화면에서 별도로 한다. 기존 상품 원본이 교체되면 관련 생성 콘텐츠를 재검수 대상으로 연결한다. AI 제작 실패가 상품 임포트 성공을 취소하지 않으며, 상품 초안 공개와 AI 자산 승인을 별개로 관리한다.
